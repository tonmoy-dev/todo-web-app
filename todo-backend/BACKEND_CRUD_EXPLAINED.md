# How CRUD Works: Backend & Database

This document explains the internal flow of Create, Read, Update, and Delete (CRUD) operations in this Django REST Framework (DRF) project.

---

## 1. The Database Layer (SQLite)
Everything starts with the **Model**. In `todos/models.py`, we define the structure of our data:
- **Table**: `todos_todo` (automatically named by Django).
- **Columns**: `id`, `title`, `description`, `author`, `is_active`, `created_at`, `updated_at`.
- **Storage**: Data is stored in the `db.sqlite3` file in your project root.

---

## 2. The Serialization Layer
Django models are Python objects, but the frontend needs **JSON**. The `TodoSerializer` in `todos/serializers.py` acts as a translator:
- **Deserialization**: Converts incoming JSON (from a React `POST` request) into a Python object that can be saved to the database.
- **Serialization**: Converts a database record (Python object) into JSON to be sent back to React.

---

## 3. The API Layer (Views & URLs)
We use DRF's **Generic Views**, which provide high-level abstractions for common patterns.

### **Read & Create** (`TodoListCreateView`)
Mapped to `GET /api/todos/` and `POST /api/todos/`.
- **GET**: Executes `Todo.objects.all()`, passes it to the serializer, and returns a JSON list.
- **POST**: Validates the incoming JSON, saves a new `Todo` record to the database, and returns the saved object with its new `id`.

### **Retrieve, Update, & Delete** (`TodoDetailView`)
Mapped to `GET`, `PATCH`, and `DELETE` on `/api/todos/<id>/`.
- **Retrieve (GET)**: Finds the specific record by `id`. Returns 404 if not found.
- **Update (PATCH/PUT)**: Modifies the specific record. `PATCH` allows updating just one field (like `is_active`).
- **Delete (DELETE)**: Removes the record from the database.

---

## 4. The CRUD Request Lifecycle
Here is what happens when you **Create a Todo**:

1.  **Frontend**: React sends a `POST` request to `http://localhost:8000/api/todos/` with JSON data: `{"title": "Buy milk", ...}`.
2.  **URL Dispatcher**: Django sees the request and matches it to the `TodoListCreateView`.
3.  **View**: The view calls the Serializer to validate the data.
4.  **Serializer**: Ensures the `title` is not empty and the data types are correct.
5.  **Database**: If valid, Django executes an SQL command: `INSERT INTO todos_todo (title, ...) VALUES ('Buy milk', ...);`.
6.  **Response**: The backend sends back a `201 Created` status with the full object (including the `id` generated by the database).
